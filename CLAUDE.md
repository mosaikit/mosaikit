# CLAUDE.md

Guidance for Claude Code in this repository. Talk to the maintainer in Italian; write code,
identifiers, comments, documentation and commit messages in English. The UI is in English by
default with Italian as a translation (i18n).

## What this is

Mosaikit: a multi-tenant web platform built out of plugins. The kernel is domain-agnostic (tenants,
users, three roles, resources, ACL, public links, KPIs, plugins). Domains live in plugins (WASM logic
in a sandbox, UI in an iframe, own data on PostgreSQL with RLS or SQLite). Products are
**distributions**, separate projects that refer to Mosaikit; Mosaikit knows none of them.
Architecture: [docs/architecture.md](docs/architecture.md).

## Sibling repositories

Three projects sit side by side in one workspace folder and must stay there:

| Repo | What |
|---|---|
| `mosaikit` | kernel (`crates/`), shell and plugin API (`ui/host`, `ui/plugin-api`), `xtask`, tests |
| `mosaikit-plugins` | official plugins (notes, tasks, contacts, maps, files, layouts, ...) |
| `geoportal` | distribution for territorial data; its own plugins and plan. Never mentioned in the docs or tests of the public repos |

Geoportal asks the kernel for what it lacks through requests to the Mosaikit session; never change the
kernel for one distribution.

## Layout

```
crates/   db, desktop, kernel, mskp, plugin-sdk, runtime, server, sql-guard
ui/       host (shell), plugin-api
xtask/    cargo xtask: dev, db, plugin, test, e2e, ci, worktree, release
tests/    e2e, manual, perf, fixtures, results (index in tests/README.md)
docs/     architecture, ui-plan, refactoring-ui, manual-tests, plugin-devkit-plan, guide, mockup
```

## Rules

- UI rules and decisions: [docs/refactoring-ui.md](docs/refactoring-ui.md). Empty lists and pages: centred
  illustration, title, text, primary action (host and plugins).
- Plan: [docs/ui-plan.md](docs/ui-plan.md). Next: [docs/plugin-devkit-plan.md](docs/plugin-devkit-plan.md).
- **Commits**: at the end of every plan phase, without asking, once checks pass. Never push (the one
  exception is the GitHub publish task, only when the user starts it). End commit messages with the
  Co-Authored-By line given by the harness.
- **Tests**: targeted while working (`cargo xtask e2e -- tests/x.spec.ts -g "title"`); normal e2e and
  `cargo xtask ci` once before merging. The full automated manual suite (`cargo xtask manual-tests`)
  runs ONLY when the user asks for a release. Still write the manual checks (docs/manual-tests.md,
  ids `P<n>-<nn>`) and their Playwright twin for each new feature.
- Keep `tests/results/test-results.md` current (generated by `cargo xtask test-report`).
- **Parallel work**: worktrees only through `cargo xtask worktree add|remove`; never delete junction
  targets (`node_modules`) by hand. At most 2-3 heavy runs at once.
- **Temp files** (worktrees, scratch targets, logs, screenshots): under `C:\tmp\mosaikit`, with
  `MOSAIKIT_TEMP='C:\tmp\mosaikit'` exported before xtask; delete when done. No temp folder next to the repos.
- Build output and worktrees belong under the development root, the parent of the workspace folder (excluded from the antivirus), not in
  `AppData\Local\Temp`. Disk is tight.
- Token economy: short replies, few parallel agents, no re-reading of large files.

## Memory

Standing decisions of the user are in the auto-memory of this project. The Geoportal
project has its own copy of the shared preferences. When a decision applies to both, save it in both.
