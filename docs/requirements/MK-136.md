---
id: MK-136
title: A level on a resource reaches the resources inside it, when their type declares it
area: security
priority: P1
status: in-progress
depends: [MK-054, MK-055, MK-041, MK-093]
decisions: [ADR-0037, ADR-0041]
acceptance:
  - A resource type declares in the manifest that its resources inherit the levels of their parent
    (the `parent` of MK-054); for such a type, the level of a person on a resource is the highest of
    their own and that of each resource above it.
  - Every answer of the kernel on sharing uses the inherited level the same way - the Java API that
    extensions call, the SQL function used by row security, the sharing endpoints and dialog, search,
    the file service and the signed links made for a file - so a person who reaches a file only
    through a folder shared with them reads it, downloads it and finds it.
  - Removing a share on a parent takes effect on everything inside it at the next request of the
    person, also for signed links not yet expired.
  - The sharing dialog and the API show, for a resource, the accesses inherited from each resource
    above it, naming that resource; a person with manage on a parent may share what is inside it.
  - Types that do not declare inheritance behave as today.
---

A file manager shares a folder and expects its content to follow, as in every team file space. The
kernel knows the parent of a resource (MK-054) but its sharing model has no inheritance (MK-055), so
an extension can compute inherited access for its own pages but every other answer of the platform
on the same item is wrong: the file service refuses the content, a signed link does not serve it,
search does not find it, and the dialog does not let the manager of the folder share what is inside
it. Declaring inheritance on the type keeps the model of MK-055 for everything else, and moves the
rule where every feature of the platform reads it.
