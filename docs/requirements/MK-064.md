---
id: MK-064
title: Accounts in the realm and one emergency administrator account
area: security
priority: P1
status: proposed
decisions: [ADR-0040]
acceptance:
  - In an installation configured with Keycloak, creating a local account creates a user in the
    realm of the organization, and the kernel stores no password for it.
  - The emergency account is turned on and off only by server configuration, answers only on a
    separate address and from configured internal networks, and requires a second factor.
  - Every use of the emergency account is written to the audit log and notified to the other
    platform administrators.
---

In a server installation with Keycloak the kernel should keep no passwords: local accounts become
users of the realm of their organization. When the identity provider is down, one emergency
administrator account still lets an operator in, under strict conditions. It extends MK-012, where
local sign-in survives an unreachable Keycloak, by keeping that path for a single, guarded account
instead of every local password.
