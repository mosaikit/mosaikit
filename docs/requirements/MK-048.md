title: Local registration confirmed by mail, which the administrator turns off
area: security
priority: P1
status: done
depends: [MK-003, MK-047]
acceptance:
  - A registered person cannot sign in before opening the link sent by mail, and can afterwards.
  - A link works once; the link can be sent again, and the new one replaces the previous one.
  - Asking for the link again never tells whether an address has an account.
  - With registration turned off, the sign-in page offers no registration and the API refuses it.
  - An administrator creates a local account with a set-password link that works once and expires; the link is mailed when the installation sends mail, otherwise shown once to the administrator, and the account signs in only after the password is set.
---

On the sign-in page a person creates a local account in an organization that allows
self-registration. The kernel sends a link to the address (Quarkus Mailer, quarkus.mailer.*); the
account signs in only after the link is opened (mosaikit.accounts.confirm-email). The link works
once, for mosaikit.accounts.confirmation-valid-for, and a new one replaces the previous ones. A
platform administrator turns self-registration off and on from the Settings page, and the change is
audited.

An administrator of an organization (for it) or of the platform (for any organization) creates a
local account for a person, with name, email and role. The account has no password: the person
chooses one with a link that works once, for mosaikit.accounts.set-password-valid-for. When the
installation sends mail (quarkus.mailer.host is set) the link is mailed and never returned; otherwise
it is returned once and the console shows it with a button that copies it. A new link replaces the
previous one. Creating the account, issuing a link and using it are audited.

## History

- 2026-10-13: the confirmation mail goes out after the account is committed and waits for the mail
  server at most `mosaikit.accounts.mail-timeout` (15 s), in two attempts on separate connections: a stuck mail server answered 500 after the
  60 s transaction timeout; now 503, the account stays and the link can be asked for again.
- 2026-10-14: administrators create local accounts with a one-time, expiring link to set the
  password, mailed when the installation sends mail and otherwise shown once to the administrator
  (issue #101); the distributions document how to set the mail server.
