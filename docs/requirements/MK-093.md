---
id: MK-093
title: "Signed, expiring links to stored files"
area: kernel
priority: P1
status: done
acceptance:
  - An extension asks the file service for a signed link to a file or to a prefix, valid for a given
    time; a link to a prefix covers every file under it.
  - A request with a valid signature is served without a session, with range requests and cache
    validators.
  - An expired or altered link is refused, and the file stays unreachable without one.
---

Viewers, external tools, embedded pages and download links in notifications fetch files without the
session of the person. Access must stay limited in time, and to what the person who asked for the
link could read, without making the files public. It extends the file service of MK-041 with links
that carry their own grant.

## History

- 2026-10-13: written from the needs of a product built on Mosaikit, reviewed from its backlog; 2 of
  its requirements depend on it.
- 2026-10-13: in progress — signed, expiring links to stored files, served without a session.
- 2026-10-13: the kernel makes signed links through `POST /api/v1/files/{extension}/links`, to a file
  or to a prefix of names (of the organization or of a team), and serves them without a session at
  `/api/v1/files/signed/...` with ranges and cache validators; an expired or altered link answers
  404, never telling whether the file exists. Stateless HMAC-SHA256 links, the key from
  `mosaikit.files.link-key` or derived with HKDF from the MK-062 master key, former keys accepted
  (migration V26). Acceptance 2 and 3 through the REST API; acceptance 1 waits for the Java API of
  extensions.
- 2026-10-13: extensions make signed links through `FileStorage.link` and `FileStorage.linkToPrefix`
  of the Java API, valid for a given time within `mosaikit.files.link-max-validity`; every
  acceptance criterion is covered by tests.
- 2026-10-13: a link made by a person carries their account and their rights (MK-055): a file
  attached to a resource is served only while they hold a level on it, so a link to a prefix never
  hands out the files of resources they cannot read and a revoked share stops their links; a creator
  out of the organization gets 404. Links made without a person, and files without a resource, as
  before (`SignedLinksFollowSharingTest`, migration V29).
- 2026-10-15: a link made before the organization was deleted (MK-130) answers not found from the
  deletion on, not when it expires (#150, `OrganizationDeletionTest`, migration V40).
