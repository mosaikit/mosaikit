---
id: MK-124
title: Service identities for internal callers of the APIs of extensions
area: security
priority: P1
status: done
depends: [MK-060]
acceptance:
  - An administrator creates a service identity with a key and the APIs of the extensions it may
    call; a request with that key reaches those APIs without a person or an organization.
  - A service identity cannot sign in to the shell and is refused on every API it was not given.
  - Every call of a service identity is in the audit log, and revoking its key refuses the next call.
---

Some callers of the APIs of extensions are not people: a reverse proxy that asks whether a request
may pass, a server that checks a personal key or reads roles. Today every call to `/api/v1/ext/*` is
tied to a person in an organization, so such callers need a fake person in an organization of their
own. A service identity is a first-class caller: it has a key, a list of the APIs it may call, no
organization and no shell, and it is audited and revocable like a personal key.

## History

- 2026-10-13: written after the proofs of a product built on Mosaikit, which needed a person in an
  organization of its own for a gateway and a map server to call its extension.
- 2026-10-13: in progress — service identities with keys, limited to the APIs they are given.
- 2026-10-13: done — identities in `service_identity` and their keys in `service_key` (migration
  V25), created by platform administrators in the page **Service identities** of the shell and with
  `/api/v1/platform/service-identities`; a key (`Authorization: Bearer mks_...`) is shown once and
  kept as a digest, and an identity has at most two live keys to rotate them. A call has the
  principal `service:<name>`, the role `service`, no account and no organization unless it names one
  it was allowed with `X-Mosaikit-Organization`; it reaches only the APIs of extensions it was given
  and, with `check-session` or `check-key`, `POST /api/v1/services/check`, which checks the session
  cookie or the personal access key of a person for a gateway (the open point of MK-060 and MK-125);
  every other path, the shell included, answers 403. The audit log records through the new channel
  `SERVICE` every refused call and the first call of each identity to each API in an hour; a revoked
  key, or a grant taken away, is refused at the next call (within `mosaikit.accounts.session-cache` on
  other kernels). Tests `ServiceIdentityTest`, `ServiceGuardTest`, `service-identities.test.ts` and
  e2e `24-service-identities`.
