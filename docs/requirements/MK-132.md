---
id: MK-132
title: Required and optional dependencies between extensions, respected by install, update and removal
area: extensions
priority: P1
status: done
depends: [MK-020, MK-030]
decisions: [ADR-0004, ADR-0019, ADR-0041]
acceptance:
  - The manifest declares required dependencies (`requires`) and optional ones, each with an id and
    a range of versions; the manifest schema and the extension guide describe both.
  - Installing an extension whose required dependency is missing, or present in a version outside
    its range, is refused, and the refusal names each such dependency and the accepted range; an
    extension copied into the extensions directory in that state is shown as incompatible with the
    same explanation.
  - An optional dependency that is missing or in another version never prevents installation or
    start; the extension runs and sees the other extension as absent (MK-133).
  - An update that would take an extension out of the range required by an installed extension is
    refused, naming the dependents, unless the administrator updates them in the same operation.
  - Removing an extension, or turning it off in an organization, is refused while an active
    extension requires it, naming the dependents; extensions that use it optionally stay active.
---

The kernel already resolves `requires` at start and leaves inactive an extension whose requirement
is missing (ADR-0004, ADR-0019), but only after the fact: an administrator learns of a missing
dependency from a status, an update can break the extensions that need the old version, and there is
no way to say "I use it when it is there". Products composed from common extensions (ADR-0041) mostly
need the optional kind: a catalog that uses a connector when it is installed, a dashboard that shows
a map when the map app is present.

## History

- 2026-10-14: written for the composition of products from common extensions (ADR-0041).
- 2026-10-15: in progress.
- 2026-10-15: implemented: `optional` in the manifest, `ExtensionDependencies` in the kernel; the
  marketplace refuses installations and updates that break a required dependency and installs
  several packages together (`POST /api/v1/marketplace/operations`); `DELETE /api/v1/extensions/<id>`
  and turning an extension off in an organization are refused while an active extension requires it.
