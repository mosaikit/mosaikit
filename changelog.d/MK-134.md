### Added

- Versioned contracts between extensions (MK-134). On the server, an extension publishes a contract
  as Java interfaces marked `@Contract` in a small API artifact, other extensions implement it, and
  the owner finds the implementations of the extensions active in the organization of the request
  with the `Contracts` bean of `kernel-api`; the manifest declares `contracts.provides` and
  `contracts.implements` with their versions. The API artifact is loaded once, in the highest
  compatible version that the extensions bring. In the frontend, `frontend.points` declares each
  major version of a point with the JSON Schema of its payload, contributions target a version as
  `point@version`, those that do not match are refused at installation with the reason, and
  `typedContributions` of `@mosaikit/sdk` gives the owner the typed contributions.
