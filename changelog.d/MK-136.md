### Added

- A level on a resource reaches the resources inside it, when their type declares it (MK-136): a
  resource type with `inherits: parent` in the manifest gets the levels of the resources above it,
  through the `parent` of the registry, as long as the types on the way inherit too; a level held
  above counts as the highest level of the same name that it includes. `Sharing` (`level`, `allows`,
  `require`, `visible`), `mk_kernel.allows()` and the row-level security built on it, the sharing
  endpoints and dialog, the file service and the signed links that people make all use it, so a
  person who reaches a file only through a folder reads it, downloads it and finds it, and removing
  the share of the folder stops it at the next request. A person with the highest level on a folder
  shares what it holds; a link to a folder opens what it holds. The dialog lists the accesses that
  come from each resource above, naming it (`GET /api/v1/sharing/resources/{extension}/{type}/{id}/inherited`),
  and extensions read them with `Sharing.inheritedGrants`. Types without the declaration behave as
  before. Migration V38.
